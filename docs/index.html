EPMS Modbus 감시 시스템 테스트 데모

전기설비 감시 흐름을 재현하고 검증한 시뮬레이션 환경

Python · Modbus TCP · Docker Compose · PostgreSQL · InfluxDB · Grafana

목차

제작 목적 실무 적용 아키텍처 전력 계층 시뮬레이터 동작 수집기와 포인트 레지스터 맵 운영 절차 이상 주입 Grafana 화면 한계와 개선 문제 해결

제작 목적

Modbus 기반으로 설치된 건물의 전기설비 감시 시스템을 테스트하기 위한 시뮬레이션 환경입니다. 실제 설비 없이도 장비 → 수집 → 저장 → 이상 감시 → 시각화까지의 흐름과 운영 방법을 검증할 수 있도록 구성했습니다.

  • 감시 시스템의 데이터 흐름을 직접 구성하고 이해합니다.
  • 이상 발생 시 확인과 대응 절차를 실습합니다.
  • 현장 장비 없이도 운영 절차와 장애 대응을 미리 연습합니다.

실무 적용: 말단 RTU만 교체

말단의 시뮬레이터를 실제 RTU로 교체하면, 수집기·DB·InfluxDB·Grafana는 그대로 사용할 수 있는 구조입니다.

유지 범위

  • 수집기의 폴링과 장애 격리 로직
  • DB 포인트 설정
  • InfluxDB 적재와 Grafana 대시보드

RS-485 구간을 쓰는 현장이라면 Modbus TCP 게이트웨이를 두면 수집기 설정 변경을 최소화할 수 있습니다.

Grafana감시 화면
  • 시뮬레이터는 Modbus TCP 502 포트로 값을 제공합니다.
  • 수집기는 PostgreSQL에서 포인트 정의를 읽어 장비를 폴링합니다.
  • HTTP 제어 API(8080)로 이상을 주입합니다.

  • 역률보상반은 전력을 흘리지 않고 알람만 담당합니다.

시뮬레이터 동작 방식

  1. 시간대별 점유율: 시간대 곡선을 분 단위로 보간해 건물 사용률을 구합니다.
  2. 건물 부하 계산: 기본 30kW와 피크 520kW 사이에서 값을 계산하고 ±2% 변동을 줍니다.
  3. 계층 합산: 분전반 합계 → 저압반 → 변압기 → 수전반 순으로 상위 값을 만듭니다.
  4. 레지스터 기록: SDM630 맵에 float32 두 워드(ABCD)로 1초마다 갱신합니다.
상위 계층은 독립 난수가 아니라 하위 합으로 계산하므로, 합계가 항상 하위 값과 일치합니다.

수집기와 포인트 설정

PostgreSQL 설정 (우선)

  • tb_point, tb_asset, tb_space, tb_site를 조인
  • 사이트가 하나인지 검증
  • Modbus 매핑 포인트만 로드

point_map.yaml (대체)

  • DB 연결 실패 시 자동 전환
  • 같은 구조의 설정 파일
  • DB 없이도 로컬 실행 가능
  • 타입별 처리: di는 Discrete Input 비트, 그 외는 float32 값에 scale을 곱합니다.
  • 장애 격리: 한 장비의 읽기가 실패해도 경고만 남기고 다음 장비를 계속 읽습니다.
  • 적재 방식: 주기마다 InfluxDB에 한 번에 씁니다.

Modbus 레지스터 맵 (SDM630 기준)

키주소 (0-base)단위설명
v_l1, v_l2, v_l30x0000, 0x0002, 0x0004V상전압
i_l1, i_l2, i_l30x0006, 0x0008, 0x000AA전류
p_l1, p_l2, p_l30x000C, 0x000E, 0x0010W상별 유효전력
pf_l10x001E-역률
p_total0x0034W총 유효전력
s_total0x0038VA총 피상전력
freq0x0046Hz주파수
kwh_import0x0156kWh총 수입 전력량 (매뉴얼 재확인 필요)

float32 값은 상위 워드부터 두 개의 16비트 레지스터로 전송합니다(ABCD 순서). 현장 장비를 연결할 때는 장비 매뉴얼의 주소와 데이터 형식이 이 맵과 일치하는지 가장 먼저 확인해야 합니다.

운영 절차

  1. 기동: docker compose up -d로 시뮬레이터와 수집기를 올립니다.
  2. 수집 확인: 수집기 로그에서 포인트 로드와 적재 여부를 확인합니다.
  3. 이상 주입: HTTP API로 과전류, 트립 같은 이상을 발생시킵니다.
  4. 화면 확인: Grafana에서 이상이 감지되고 상태가 바뀌는지 확인합니다.

실행 명령

# 시뮬레이터와 수집기 빌드 및 실행
docker compose up -d --build epms-modbus-sim epms-modbus-collector

# 수집 로그 확인 (DB 로드 여부 포함)
docker logs epms-modbus-collector 2>&1 | grep -E "point_map|DB 로드 실패"

정상 실행되면 point_map: DB에서 25개 포인트 로드와 적재 N개 포인트 로그가 출력됩니다.

이상 상황 주입

# 장비 7번에 과전류 주입
curl -X POST "http://localhost:8080/inject?scenario=OVERCURRENT&unit=7"

# 모든 장비의 이상 해제
curl -X POST "http://localhost:8080/inject?scenario=CLEAR&unit=all"

# 현재 상태 조회
curl "http://localhost:8080/status"

시뮬레이터 컨테이너 콘솔에서는 <unit|all> <fault> 형식으로 입력합니다. 예: 7 overcurrent, all clear

Grafana 감시 화면

  • 상단: 이상 주입 버튼과 전체 복구
  • KPI: 총 전력, 역률, 누적 전력량, 변압기 부하율
  • 단선도: 층별 분전반 전력과 차단기 상태
  • 하단: 전압, 전류 추이와 분전반별 부하

이상을 주입하면 상태 패널과 차트가 즉시 바뀌고, 복구 후 정상값으로 돌아옵니다.

한계와 개선 과제

  • 검증: kwh_import 주소(0x0156)는 SDM630 매뉴얼로 재확인이 필요합니다.
  • 상태 보존: 이상 상태가 메모리에만 있어 시뮬레이터 재시작 시 초기화됩니다.
  • 통신 구간: RS-485를 쓰는 현장은 Modbus TCP 게이트웨이 설정이 추가로 필요합니다.
  • 시연 화면: Grafana Canvas 기반 Modbus 시연 화면을 마무리할 예정입니다.

문제 해결

DB 로드가 YAML로 대체되는 경우

수집기가 PostgreSQL이 준비되기 전에 연결을 시도하면 Connection refused가 발생하고 YAML로 대체됩니다. 로그 시각을 PostgreSQL 기동 로그와 비교해 기동 순서 문제인지 확인합니다. 재발을 막으려면 postgres에 헬스체크를 추가하고 수집기의 depends_on에 condition: service_healthy를 지정합니다.

고정 IP 지정 시 네트워크 오류

no configured subnet contains IP address 오류는 네트워크에 subnet을 정의하지 않고 고정 IP를 지정했을 때 발생합니다. 수집기는 서비스 이름(epms-modbus-sim)으로 접속하므로 고정 IP를 제거하는 것을 권장합니다.
